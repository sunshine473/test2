# 开发计划

## 里程碑

- **M1（素材采集 MVP）**：完成 collector 模块，能从 3+ 信息源采集并输出选题清单
- **M2（内容生成）**：完成 generator 模块，能基于选题生成 Markdown 文章草稿
- **M3（流水线打通）**：Skill 调度 + 内容仓库 + 发布分发全链路跑通

## 协作规则

- 认领任务：在"负责人"列填写 `Claude` 或 `Codex`，状态改为 `进行中`
- 约束：状态为"进行中"时必须有负责人，不允许"待认领 + 进行中"的组合
- 完成后更新状态为 `Done`，"复盘"列写一句话结论，详细复盘写入 `docs/复盘记录.md`
- 如果任务有依赖关系，先完成前置任务再认领后续任务
- 遇到阻塞时在"备注"列写明原因（前缀 `BLOCKED:`），不要空等，可先做其他任务
- 完成任务后检查 `CLAUDE.md`、`README.md` 是否需要同步更新

## 验证方式

### M1 验证（素材采集）
- 结构验收：`src/collector/` 和 `src/config/sources.yaml` 目录文件创建完成
- 功能验收：运行 `python src/collector/main.py`，输出 JSON 格式选题清单（至少 3 个信息源）

### M2 验证（内容生成）
- 结构验收：`src/generator/` 和 `content/` 目录结构创建完成
- 功能验收：运行 `/write "选题标题"`，在 `content/drafts/` 生成 Markdown 文件

### M3 验证（流水线打通）
- 功能验收：从 `/collect` 到 `/publish` 全流程跑通一篇文章
