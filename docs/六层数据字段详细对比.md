# 六层数据字段详细对比 / Six-Layer Data Field Comparison

本文档详细对比六层架构中每层的数据字段变化，帮助理解数据在流水线中的演进过程。

---

## 数据流转概览

```
Layer 1: 采集层 (50条) → RawMaterial[]
    ↓ 清洗、去重、翻译
Layer 2: 整理层 (42条) → MaterialPool
    ↓ 筛选、评分、推荐
Layer 3: 策划层 (5个) → TopicCandidate[]
    ↓ 人工选择
Layer 4: 创作层 (1篇) → DraftPackage
    ↓ 格式转换
Layer 5: 包装层 (3个平台) → PublishPackage
    ↓ 调用API发布
Layer 6: 分发层 (3个结果) → PublishResult
```

---

## 字段演进规律

### 1. 逐层精简

```
Layer 1: 13 个字段（原始素材）
Layer 2: 21 个字段（补全信息）
Layer 3: 20 个字段（聚焦选题）
Layer 4: 23 个字段（生成文章）
Layer 5: 7 + 11×N 个字段（多平台格式）
Layer 6: 13 + 9×N 个字段（发布结果）
```

### 2. 字段转换

| 转换类型 | 示例 |
|---------|------|
| 补全 | `summary`: 可选 → 必需 |
| 重命名 | `title` → `topic_title` → `title` |
| 拆分 | `content` → `article_markdown` + `payloads[].content` |
| 聚合 | 多个素材 → `source_items[]` |
| 删除 | `cluster_id`（策划后不需要） |
| 新增 | `payloads`（包装层新增） |

### 3. 数据量变化

```
50 条素材 → 42 条（去重）→ 5 个选题 → 1 篇文章 → 3 个平台格式 → 3 个发布结果
```

## 关键设计原则

### 1. 单向流动
数据只能向前流动，不能回退：
```
采集 → 整理 → 策划 → 创作 → 包装 → 分发
```

### 2. 可回放
每层输出都保存为 JSON，可以重跑：
```
content/
├── raw/          # 可以重跑整理
├── normalized/   # 可以重跑策划
├── topics/       # 可以重跑创作
├── drafts/       # 可以重跑包装
├── packages/     # 可以重跑分发
└── published/    # 最终结果
```

### 3. 版本追踪
每层都有版本字段：
- `normalizer_version`
- `planner_version`
