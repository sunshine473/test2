### T23 — 修复 Telegram Bot offset 持久化与工作流依赖
- **负责人**: Codex
- **产出**: `.github/workflows/telegram-bot.yml`, `src/bot/requirements.txt`, `docs/开发计划.md`
- **问题与解决**: Telegram Bot 在 GitHub Actions 中暴露了 `write/publish` 工具，但工作流仅安装 collector+bot 依赖，导致发布链路调用时会因为依赖缺失失败。已在 workflow 安装步骤补充 `src/publisher/requirements.txt`，并在 bot 依赖中补充 `google-genai`，覆盖写作链路的核心运行时依赖。

- **验收证据**: `python -m compileall -q src/bot` 通过；workflow 中 `cache-dependency-path` 与 `Install dependencies` 已同步新增 publisher 依赖。
- **后续**: 建议补一个 bot 集成冒烟测试（至少覆盖 `check_status` / `publish` 工具导入路径），防止后续再出现依赖漂移。

### T22 — 修复 Skill 定义格式，迁移至 `.claude/skills/`
- **负责人**: Claude
- **产出**: `.claude/skills/collect/SKILL.md`, `.claude/skills/publish-to-wechat/SKILL.md`, `.claude/skills/get-inspiration/SKILL.md`
- **问题与解决**: 项目中三个 Skill（collect、publish-to-wechat、get-inspiration）均放在项目根目录 `skills/` 下，且缺少 YAML frontmatter 元数据，导致 Claude Code 无法识别和调用。Claude Code 的 Skill 自动发现机制只扫描 `.claude/skills/<name>/SKILL.md` 路径，且需要 frontmatter 中声明 `user-invocable: true` 等字段。将三个 Skill 迁移到 `.claude/skills/` 下，并补充完整的 YAML frontmatter（description、user-invocable、allowed-tools、argument-hint）。
- **经验**: Skill 定义必须严格遵循 Claude Code 规范：① 路径必须是 `.claude/skills/<name>/SKILL.md`；② 必须包含 YAML frontmatter 声明元数据；③ 仅放在自定义目录下的 Markdown 文件只是文档，不会被注册为可调用命令。**这个问题已反复出现多次，后续创建 Skill 时务必检查路径和格式。**
- **验收证据**: `/collect` 命令在 Claude Code 中可被识别和调用
- **后续**: 旧 `skills/` 目录待清理；M2 新增的 `/write` 和 `/publish` Skill 需直接在 `.claude/skills/` 下创建

### T21 — 素材采集增加"文章发布时间"字段
- **负责人**: Codex
- **产出**: `src/collector/notion_output.py`, `docs/开发计划.md`
- **问题与解决**: 采集结果虽已有 `published_at` 原始字段，但 Notion 库缺少可直接筛选的发布时间列。新增数据库字段“文章发布时间”（date），写入时将各来源时间（ISO/RFC822）统一解析为 ISO8601 后入库；无有效时间则留空，避免脏数据。
- **经验**: 采集字段应区分“原始字段”与“可运营字段”，后者需要在落库层做格式归一化，便于筛选和排序。
- **验收证据**: `python -m py_compile src/collector/notion_output.py` 通过；`_ensure_schema` 已包含“文章发布时间”自动补齐逻辑，`_create_page` 已写入发布时间。
- **后续**: 可在主流程输出增加“发布时间缺失率”统计，持续优化各来源时间字段覆盖率。

### T20 — 接入 YouTube Data API v3 采集器并配置 Top20 频道
- **负责人**: Codex
- **产出**: `src/collector/sources/youtube_api.py`, `src/collector/main.py`, `src/config/sources.yaml`, `src/collector/dedup.py`, `skills/collect/SKILL.md`, `README.md`, `CLAUDE.md`, `docs/开发计划.md`
- **问题与解决**: 现网环境下 YouTube RSS 链接稳定返回 404，导致频道配置存在但无法采集。新增 YouTube Data API v3 适配器，采用 `channels.list(forHandle/id)` + `playlistItems.list` 获取最新视频；并在配置中预置 20 个优质频道（官方/研究/工程混合）。同时修复去重逻辑对 YouTube URL 的归一化，避免不同视频被错误合并。
- **经验**: 对高价值平台优先使用官方 API，解析网页或 RSS 只作为备选；URL 去重规则必须按站点特性做细分。
- **后续**: 建议补充 `yt-dlp` fallback，在 API key 缺失或配额受限时自动降级采集。

### T6 — 实现 LLM 打分排序（`scorer.py`）
- **负责人**: Codex
- **产出**: `src/collector/scorer.py`, `src/collector/main.py`, `docs/开发计划.md`
- **问题与解决**: 采集结果缺少优先级，无法直接产出“可用选题清单”。新增可解释打分器，按来源权重、分类权重、时效、关键词、聚类规模及 HN 点赞进行综合评分，并在主流程排序输出。

### T5 — 实现素材去重 + 聚类（`dedup.py`）
- **负责人**: Codex
- **产出**: `src/collector/dedup.py`, `src/collector/main.py`, `docs/开发计划.md`
- **问题与解决**: 多源采集存在重复 URL 与同题异链，直接输出噪声过大。新增 URL 归一化去重 + 标题相似度聚类，并输出 `cluster_id` / `cluster_size` 元数据。
- **经验**: 采集系统的“可读性”核心在去重聚类，排序前先降噪能显著提升后续打分质量。
- **后续**: 可引入语义向量聚类替代标题字符相似度，提升跨语言聚类效果。

### T17 — 将素材采集改为强制同步 Notion（失败即退出）
- **负责人**: Codex
- **产出**: `src/collector/main.py`, `src/collector/notion_output.py`, `docs/开发计划.md`
- **问题与解决**: 当前采集链路对 Notion 同步是可选，存在“本地有输出但库内无记录”的数据断裂风险；同时实际 Notion 库为新 `data_source` 结构，旧写法按数据库属性写入会失败。将策略升级为强制同步：缺少 `NOTION_API_KEY`/`NOTION_DATABASE_ID`、采集为空、写入异常或写入 0 条时直接退出；并在写入层兼容 `data_source`，自动补齐缺失字段后再写入。
- **经验**: 面向生产内容流，采集结果必须落库，失败要显式失败；对 Notion 新旧 schema 需要做兼容，避免因字段结构差异导致全量失败。
- **后续**: 可补充重试机制与失败补偿队列，避免短时网络抖动导致整次任务失败。

### T16 — 实现采集结果自动同步 Notion（支持开关）
- **负责人**: Codex
- **产出**: `src/collector/main.py`, `docs/开发计划.md`
- **问题与解决**: 原流程仅在传入 `--notion` 时才同步，容易遗漏。新增自动判定逻辑：检测到 `NOTION_API_KEY` 与 `NOTION_DATABASE_ID` 时默认同步；支持 `--no-notion` 显式关闭，并保留 `--notion` 强制开启。

### T3 — 实现 GitHub Trending 信息源适配器
- **负责人**: Codex
- **产出**: `src/collector/main.py`, `src/collector/sources/twitter.py`, `src/collector/requirements.txt`, `src/config/sources.yaml`, `docs/开发计划.md`
- **问题与解决**: 联调时默认全源采集包含 Tavily/Twitter，执行耗时过长容易被误判卡住；同时 Twitter 搜索结果混入站外噪声、Notion 依赖未声明。将默认采集源调整为 `rss,github`，为慢源增加提示，Twitter 增加 `x.com/twitter.com` URL 过滤，补充 `notion-client` 依赖并修正配置中的错误 handle。
- **经验**: 采集链路要区分“默认快路径”和“显式慢路径”，否则协作调试阶段会持续出现“卡住”感；聚合搜索类数据必须做域名/路径过滤才能保证可用性。
- **后续**: T2（Hacker News 独立适配器）、T4（微博/百度热搜适配器）仍待认领；建议后续补充去重与评分后再做完整 `/collect` Skill 串联。
